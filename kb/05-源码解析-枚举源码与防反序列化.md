## enum 的真相：编译成 class、Enum 基类、序列化防线

## enum 是语法糖还是"一等公民"？

`enum` 看起来是简单的常量列表，实际是**编译器生成的完整类**：

- 每个枚举类型编译成 `final class Xxx extends Enum<Xxx>`
- 每个枚举常量 = 类的 `static final` 实例
- 编译器自动生成 `values()` / `valueOf(String)` / `$VALUES` 数组

这套设计让枚举天然拥有：类型安全、单例保证、序列化防破坏。

---

## 枚举编译后的样子是什么？（javap 视角）

```java
// 源码
public enum Color {
    RED, GREEN, BLUE
}
```

```java
// javac 编译后等价于（javap -p 反编译视角）：
public final class Color extends Enum<Color> {
    public static final Color RED = new Color("RED", 0);
    public static final Color GREEN = new Color("GREEN", 1);
    public static final Color BLUE = new Color("BLUE", 2);

    private static final Color[] $VALUES =
        new Color[] { RED, GREEN, BLUE };

    // 构造器私有（外部无法 new）
    private Color(String name, int ordinal) {
        super(name, ordinal);
    }

    // 编译器生成
    public static Color[] values() {
        return $VALUES.clone();          // 防御性克隆
    }

    public static Color valueOf(String name) {
        return Enum.valueOf(Color.class, name);
    }
}
```

**关键点**：

- 类被声明 `final`（不能再继承枚举）
- 构造器私有（不能 new 新常量）
- `values()` 每次返回**克隆数组**（防外部修改）

## Enum 基类源码里有什么防线？

```java
public abstract class Enum<E extends Enum<E>>
        implements Comparable<E>, Serializable {

    private final String name;      // 常量名（RED）
    private final int ordinal;      // 声明序号（0,1,2...）

    protected Enum(String name, int ordinal) {
        this.name = name;
        this.ordinal = ordinal;
    }

    public final String name() { return name; }
    public final int ordinal() { return ordinal; }
    public String toString() { return name; }

    // 比较按 ordinal
    public final int compareTo(E o) {
        return this.ordinal - o.ordinal;
    }

    // 泛型签名 E extends Enum<E>：
    // 保证 compareTo 参数是"同类型枚举"，编译期类型安全

    // ⭐ 序列化防线：
    private void readObject(ObjectInputStream in)
            throws IOException, ClassNotFoundException {
        throw new InvalidObjectException("can't deserialize enum");
    }
    // 直接反序列化会被拦截！
    // 实际反序列化走 ObjectInputStream 的枚举专用路径：
    // Enum.valueOf(enumType, name) → 返回已有单例，不新建对象
}
```

## 为什么枚举是"最佳单例"？

```java
public enum Config {
    INSTANCE;
    // 字段、方法随便加
    private final Properties props = loadProps();
    public String get(String key) { return props.getProperty(key); }
}
```

**四道防线**：

| 攻击途径 | 枚举的防御 |
|---|---|
| 多线程 new | 类加载器保证只初始化一次（线程安全） |
| 反射 `newInstance()` | 检查 `isEnum()` → 抛 `IllegalArgumentException` |
| 反序列化 | `readObject` 抛异常 + 枚举专用路径返回单例 |
| 克隆 | `clone()` 对枚举抛 `CloneNotSupportedException` |

```java
// 反射攻击验证：
Constructor<Config> c = Config.class.getDeclaredConstructor();
c.setAccessible(true);
c.newInstance();   // ❌ IllegalArgumentException:
// "Cannot reflectively create enum objects"
```

这就是 **Effective Java 推荐枚举单例**的原因：一行代码，四道防线全开。

## values()/valueOf() 的细节是什么？

```java
// values()：每次返回克隆数组（防御性）
Color[] all = Color.values();     // 每次 new 数组

// 高频遍历优化：缓存
private static final Color[] ALL = Color.values();

// valueOf：不存在抛 IllegalArgumentException（非 null 语义）
Color c = Color.valueOf("RED");   // OK
Color c2 = Color.valueOf("NOPE"); // ❌ IllegalArgumentException

// null 处理：valueOf(null) 抛 NPE
// 安全转换：
public static Color safeValueOf(String name, Color fallback) {
    if (name == null) return fallback;
    try { return Color.valueOf(name); }
    catch (IllegalArgumentException e) { return fallback; }
}
```

## 枚举 switch 的编译真相是什么？

```java
switch (color) {
    case RED -> ...;
    case GREEN -> ...;
}
```

**编译产物**：编译器生成 `$SwitchMap$Color` 数组（按 ordinal 索引），把枚举 switch 转成 **int 数组查表**：

```java
// 等价于：
static final int[] $SwitchMap$Color = new int[Color.values().length];
static {
    $SwitchMap$Color[Color.RED.ordinal()] = 1;
    $SwitchMap$Color[Color.GREEN.ordinal()] = 2;
}

// switch 编译为：
switch ($SwitchMap$Color[color.ordinal()]) {
    case 1: ...
    case 2: ...
}
```

## 枚举与数据库/JSON 怎么映射？

```java
// ⚠️ 别直接存 name()：枚举改名 = 历史数据全废
public enum OrderStatus {
    CREATED(1), PAID(2), SHIPPED(3), COMPLETED(4), CANCELLED(5);

    private final int code;
    OrderStatus(int code) { this.code = code; }
    public int code() { return code; }

    public static OrderStatus fromCode(int code) {
        for (OrderStatus s : values()) {
            if (s.code == code) return s;
        }
        throw new IllegalArgumentException("未知状态码: " + code);
    }
}
```

- 数据库 / 跨系统传输：用**稳定的 code 字段**，不用 name()
- JSON：Jackson 默认输出 name()，可用 `@JsonValue` 指向 code
- 反序列化失败场景：枚举改名后老 JSON 数据 `valueOf` 抛异常 → `@JsonCreator` 兜底

## 一条主线串起枚举防线

- 枚举编译成 `final class extends Enum<E>`，常量是静态实例
- 构造器私有 + 类 final = 常量集合封闭
- `values()` 克隆返回；`valueOf` 找不到抛异常
- 枚举单例四道防线：类加载 / 反射检查 / 序列化拦截 / clone 拒绝
- `E extends Enum<E>` 自限性泛型保证类型安全
- 跨系统传输用 code 字段，别用 name()

> 枚举是 Java"语法糖"里最扎实的一个：编译器生成 + JVM 保护 + 序列化特判，三层机制让它成为常量、单例、状态机的首选。
