# 【源码解析】接口演进与默认方法冲突

## 从纯抽象到能力完备：default 方法的三条冲突规则

<span style="color:#888">Java 语言核心 · 第 04 讲延伸 · 源码专题</span>

---

## 接口为什么"活"了？

JDK 8 之前，接口是纯粹的抽象契约：只有抽象方法 + `public static final` 常量。JDK 8 为了给 `Collection` 等老接口加方法（`forEach`/`stream`）而又不破坏所有实现类，引入了 **default 方法**——接口第一次拥有了"默认实现"。

- **JDK 8**：default 方法 + static 方法（JEP 101）
- **JDK 9**：private 方法（JEP 213，default 方法的内部复用）
- 演进动机永远是同一个：**给已有接口加能力，不破坏实现类**

---

## default 方法：接口里怎么会有实现？

```java
// JDK 8 源码：Collection 新增的 default 方法
public interface Collection<E> extends Iterable<E> {

    default void forEach(Consumer<? super E> action) {
        Objects.requireNonNull(action);
        for (E e : this) {
            action.accept(e);
        }
    }

    default boolean removeIf(Predicate<? super E> filter) {
        Objects.requireNonNull(filter);
        boolean removed = false;
        final Iterator<E> each = iterator();
        while (each.hasNext()) {
            if (filter.test(each.next())) {
                each.remove();
                removed = true;
            }
        }
        return removed;
    }

    default Spliterator<E> spliterator() { ... }
}
```

**实现类的三个选择**：

1. 不重写 → 继承默认实现
2. 重写 → 用自己的实现
3. 显式调用默认：`InterfaceName.super.method()`

**为什么能"不破坏"实现类？**

- 老实现类（JDK 7 编译的）没实现 `forEach` → 加载时用接口的 default
- 字节码层面：default 方法编译进接口的常量池，实现类通过 `invokespecial InterfaceName.super.method` 调用

## static 和 private 方法（JDK 8/9）是什么？

```java
public interface MathUtils {
    // static：接口名直接调用（JDK 8）
    static int square(int x) { return x * x; }

    // private：仅供接口内部复用（JDK 9）
    private String normalize(String s) {
        return s.trim().toLowerCase();
    }

    default String format(String s) {
        return normalize(s);          // 调 private 方法
    }
}
```

**规则**：

- static 方法不能访问实例状态（接口无状态）
- private 方法只能被同接口的 default/static 方法调用
- private 方法不能是 abstract（显然）

## 菱形冲突的三条解决规则是什么？

```java
// 场景：类实现两个接口，都提供同名 default 方法
interface A { default void m() { System.out.println("A"); } }
interface B extends A { default void m() { System.out.println("B"); } }
interface C { default void m() { System.out.println("C"); } }
```

**规则 1：类优先**——类的声明/继承方法优先于接口 default

```java
class Parent { public void m() { System.out.println("Parent"); } }
class Child extends Parent implements A { }
new Child().m();   // "Parent"（类赢，无冲突）
```

**规则 2：最具体**——子接口的 default 覆盖父接口的

```java
class X implements B { }     // B extends A
new X().m();                 // "B"（B 比 A 更具体）
```

**规则 3：显式 override**——规则 1/2 无法裁决时，必须手动指定

```java
class Y implements B, C {    // B、C 都"最具体"→ 冲突
    @Override
    public void m() {
        B.super.m();         // 手动选择
        // 或 C.super.m();
    }
}
// 不写 override 编译错误：
// "class Y inherits unrelated defaults for m() from types B and C"
```

## default 方法为什么不能碰 Object 方法？

```java
// 接口不能声明 default equals/hashCode/toString！
interface Bad {
    // default boolean equals(Object o) { return true; }
    // ❌ 编译错误：
    // "default method equals in interface Bad overrides a member of java.lang.Object"
}
```

**原因**：`Object` 的方法优先级最高。类的 `Object` 实现（地址比较）永远优先于接口 default。允许接口定义会造成语义混乱（类里到底用哪个？）。

## 给公共接口加方法的安全姿势是什么？

```java
// 场景：你的库接口有 100 个实现，想加 clear()
public interface Cache<K, V> {
    V get(K key);
    void put(K key, V value);

    // ✅ 方案：default + 安全兜底异常
    default void clear() {
        throw new UnsupportedOperationException(
            getClass().getName() + " 未实现 clear()");
    }
    // 老实现调用 clear() → 明确报错（Fail-fast）
    // 新实现重写 clear() → 正常使用

    // ❌ 反例：default 空实现
    // default void clear() { }   // 老实现"悄悄"获得空行为
    // → 缓存不清理 + 无任何提示 = 静默事故
}
```

**三条原则**：

1. 默认行为必须"安全"：宁可抛异常，不可静默错误
2. 优先考虑新接口（如 `Clearable`）+ 实现类按需实现
3. 发布变更日志说明 default 影响

---

## 一条主线串起接口演进

- 接口演进：JDK 8 default/static → JDK 9 private，动机都是**兼容**
- default 方法 = 实现类可选的钩子，不是必须的契约
- 菱形冲突三规则：**类优先 → 最具体 → 显式 override**
- 接口不能 default equals/hashCode/toString（Object 优先）
- 给公共接口加方法：default 必须"安全兜底"，优先新接口

> 接口是现代 Java 设计的核心词汇：**契约 + 演进能力**并重。读懂 default 方法的兼容性设计，就读懂了 JDK 为什么敢在 25 年间不断给老接口"加方法"。
